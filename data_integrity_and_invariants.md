## Corrections already baked into `current_df.csv`

**Legacy opponent-identity scramble — diagnosed and fixed, 26 rows.** Two clusters in the base dataset had the loser slot (name, `fighter_url`, stat line, DOB) permuted across fights on the same card: **UFC 19–23** (1999-03-05 to 1999-11-19, 16 rows) and **UFC Fight Night: Holloway vs. The Korean Zombie** (2023-08-26, 10 of 13 rows). Symptoms: fighters listed as fighting themselves (Kenichi Yamamoto), missing real title fights (Tito Ortiz's UFC 22 loss to Frank Shamrock replaced by a phantom win). Root cause was the legacy base ETL — **not** greco1899's source (verified clean three ways) and **not** the current `dataset_processing_pipeline.py`. All 26 rows were re-scraped from live UFCStats and the full dataset rebuilt through `run_refresh.py`'s chain; `current_df.csv` is correct as of that rebuild. Not a code change — v2.6 scoring lock intact; GOAT ranking order unchanged.
- **This correction stays frozen unless the rows are force-re-scraped.** `ude_scrape_new.py` excludes UFC 19–23 by hardcoded event list, and cluster 2 is already in the base, so a routine refresh never re-touches either. `validate_dataset_regeneration` diffs clean against `current_df.csv` going forward.
- **How to re-check this bug class:** set-compare every row's `{fighter_1, fighter_2}` against greco1899's `ufc_fight_details.csv` URL→BOUT map across all rows. Expect ~21 benign name-spelling variants (`Waldo Cortes-Acosta`/`Waldo Cortes Acosta`, `Zach Reese`/`Zachary Reese`, `Montse Rendon`/`Montserrat Rendon`, …) — same person, same fight, not corruption. Anything past that warrants investigation. Memory: `project_legacy_opponent_scramble.md`.

**`fighters_df.csv` bio data — do not sync toward greco1899's `ufc_fighter_tott.csv`.** That public file swaps the names *and* DOBs of two distinct real fighters: **Jose Montanha** (Montanha is his surname; DOB 1996-08-25; has real scored fights) and **Henrique Da Silva Lopes** (nicknamed "Montanha"; DOB 1985-03-08). The project's own scrape has both correct, verified live against UFCStats. More broadly the self-scrape has strictly better bio coverage than greco (DOB +265 fighters, Reach +105, Height +103, Stance +89) — the scrape-it-yourself step in the update workflow is doing real work, not duplicating an adequate public source.

**`is_title_bout` interim/undisputed conflation — diagnosed and fixed.** `create_is_title_bout_column` checked `is_title` (matches any string containing "Title Bout") before `is_interim`, but an interim title's raw string (e.g. `"UFC Interim Light Heavyweight Title Bout"`) contains both substrings — so every interim bout was coded `2` (undisputed) identically to a real undisputed title, and the `is_interim` branch producing `1` was unreachable. This propagated into `is_champion` (an interim championship read as a full undisputed one — concretely, two fighters could show as simultaneous undisputed champions of the same division, which is impossible) and into `update_title_defenses`, which had its own independent bug on top (`is_tb > 0` instead of `is_tb == 2`, so it would have kept miscounting even after the first fix). Both fixed; `current_df.csv` regenerated. `title_defenses_fighter_1`/`_2`'s pre-existing "undercounts final total by 1" caveat (see `data_dictionary.md`) is a separate, still-true limitation, unrelated to this one.
- **A related suspected bug, in `multi_division_championship_bonus`, was investigated and found NOT to be real** — the real scoring loop passes `weight_class_cleaned` into that function, already collapsing interim/undisputed correctly, so no fix was needed there. Worth remembering as a caution: verify any suspected bug against the actual function and its actual inputs, not a hand-rolled simulation of its logic — a simulation using the wrong column (raw `weight_class` instead of `weight_class_cleaned`) produced a false positive here.
- **GOAT ranking impact:** top-20 order changed at the top — Jon Jones now edges Georges St-Pierre (previously reversed); Justin Gaethje fell out of the top 10 (his inflated interim-title credit removed); Kamaru Usman and Khamzat Chimaev entered the top 20, Aljamain Sterling and Petr Yan dropped out. Current table in `canonical_project_state.md` §2a.

## Invariants that look like cleanup targets but are load-bearing

- **The `pd.isna(anchor_age)` guard in `_age_logit_offset` / `_age_multiplier`** (`ude_points_algorithm.py`) is deliberate. Without it, neutral-calibration years (NaN `anchor_age`) fall through into `slope * NaN`, and `max(MIN, min(MAX, NaN))` silently resolves to the clip **ceiling** (1.5×) rather than a 1.0× no-op — every decisive fight in those years gets a flat unconditional bonus. This is the project's one confirmed bug class: **a neutral/fallback state resolving to a clip boundary instead of a true no-op.** Any new bounded multiplier (e.g. a future era-strength calibration) must be designed against it from the start.
- **`_dominance_magnitude`'s numeric output feeds the locked scoring engine** (`dominance_adjustment`, `perf_scale`, `method_pdi_residual` all at once). The `decisive_wins`/`close_wins`/`ties` misclassification was fixed at the classification-bucketing step, by rounding a *separate copy* of the phase magnitudes — never by touching `_dominance_magnitude`'s formula. Changing its output at all breaks bit-for-bit reproducibility against v2.6 for zero scoring benefit.
- **`career_point_gain` in `rank_fighters_by_shrunk_ude_rate` sums `ude_points_diff_fighter_1`/`_2` from the rows in the passed dataframe** — not a career-ledger snapshot via `get_latest_ude_points_with_details`. Identical for the full population; different for any filtered (by-division, by-gender) view, where a ledger snapshot bleeds in points from fights in *other* divisions that sit chronologically between two fights in the filtered set (Frankie Edgar's old LW title run showing up as "FW value"; Jose Aldo's mid-career BW stint deflating his FW score). Reverting to the snapshot reintroduces cross-division contamination.
- **`rank_fighters_by_shrunk_ude_rate_by_gender`:** `'Catch Weight Bout'`/`'Open Weight Bout'` rows (~85 fights) are excluded from both `'M'` and `'F'` — a small per-fighter undercount for anyone who had one. Women's featherweight (WFW, ~30 total fights) returns no qualifier at `min_fights=10`.
- **Name-keyed ranking collisions:** `rank_fighters_by_shrunk_ude_rate` and its wrappers key on the fighter *name string*. Distinct fighters who share a name (e.g. two "Bruno Silva"s) collide into one inflated/garbled row. Harmless at `min_fights=10` for the known cases so far, but check name uniqueness before trusting any new sub-population ranking.
- `calculate_phase_magnitude_and_pdi` was edited post-v2.6-lock to fix the `decisive_wins`/`close_wins`/`ties` misclassification above by rounding a separate copy of the phase magnitudes before classification bucketing — verified to leave `pdi_margin` and every scored output bit-identical.

## Working note: how to investigate a surprising ranking or number

A surprising ranking shift is a signal to trace the actual mechanism before explaining it, not to pattern-match to the most recent change. During the v2.6 build the v1→v2→v3 GOAT list movement was first attributed to the own-age fix; the real driver was the NaN-clip bug above, still live at the time. The by-division ranking corrections came out the same way — a face-validity check ("why does Brendan Allen outrank Adesanya at MW?") surfaced the `career_point_gain` contamination, not a test. The `is_title_bout` bug above was found the same way too — a routine `value_counts()` check while scoping an unrelated research task, not a targeted audit.
