# UDE Points — Revision History

Chronological record of fixes, decisions, and audits. `canonical_project_state.md` reflects only the current state; this document explains how it got there. Not required reading to continue the project — consult it only when the "why" behind a past decision matters.

---

## 2026-08-21

1. **Age Sign Fix (superseded same day).** `_age_multiplier` no longer wraps the fitted logistic slope in `abs()` uniformly for both sides. First pass applied the unwrapped signed slope to *both* `opponent` and `own` sides — measurably shrank the own-age bonus for wins past reference age into a penalty (own-side post-slope is empirically negative). Corrected same day, see #7.

2. **Bonus Anchor Standardization.** `streak_adjustment` seeded with and measured against `raw_base_points` (±3), matching `title_defense_bonus`, before both feed `combined_bonuses` and get scaled once by `perf_scale`. Removed the prior compounding path where streak bonus rode on top of championship/dominance multipliers on title-bout fights.

3. **Rolling Age/Method Calibration Window.** `_build_temporal_calibration_cache` moved to a trailing 5-year window (`CALIBRATION_ROLLING_WINDOW_YEARS`), falling back to full expanding history only below `CALIBRATION_MIN_FIGHT_OBSERVATIONS` (1,000) fights. Confirmed on the live dataset: fallback engages 1999–2011, rolling window active from 2012 onward (2026 uses 2,577 fights vs. 8,226 under the old expanding approach).

4. **`ABSOLUTE_SWING_CAP` Diagnostics.** Added execution logging + `df.attrs` recording how often the 60-point circuit breaker binds. Measured: 0/16,904 (0%) — cap was dormant, not load-bearing.

5. **PDI Margin Multi-Layer Review (decision, no code change).** Audited whether `dominance_adjustment`, `perf_scale`, and the method×PDI residual constitute redundant point creation from the same signal. Finding: `dominance_adjustment` and `perf_scale` both derive from the identical `pdi_margin / PDI_MARGIN_SCALE`, so they move in the same direction on every fight (~35% of a title-defense fight's total PDI-driven swing traced to this directional stacking). `perf_scale` structurally cannot generate points on its own (shrink-only, bounded 0.20–1.0) — accepted as a bounded tradeoff, not a defect.
   - Considered decoupling `perf_scale` onto method decisiveness or `phases_won` — rejected. Method already has a dedicated calibrated channel (`method_pdi_residual_points`); `phases_won` is itself a discretization of the same PDI data `dominance_adjustment` already consumes. No unclaimed orthogonal signal existed for `perf_scale` to borrow without creating a new collision.

6. **`min_fights` Floor on Shrunk-Rate Ranking.** `rank_fighters_by_shrunk_ude_rate` gained an optional `min_fights` parameter. Bayesian shrinkage alone (`prior_strength=10`) was insufficient at very small n — a 4-fight career (Murilo Bustamante, 2 of 4 fights title-bout wins) still ranked top-20 despite an 84% shrinkage haircut, with rank unstable (8→55) across `prior_strength` 5–30. `population_mean_rate` is still computed over the full unfiltered population so the shrinkage target itself isn't biased by the floor.

7. **Own-Age Achievement vs. Opposition-Quality Split.** `_age_multiplier` given a different sign convention per side. `opponent` side keeps the signed `opponent_post_slope` (an opposition-quality discount, correctly signed). `own` side switched to `abs(own_post_slope)` deliberately — an achievement-under-adversity signal, matching how every other UDE component (`higher_rated_opponent_bonus`, `opponent_quality_adjustment`) rewards clearing a harder bar with *more* credit, never less. Not a reversion to #1's bug: that bug applied `abs()` without asking whether both sides measure the same kind of quantity — they don't.

8. **Smoothed Own-Age Opponent Gate.** `own_age_adjustment`'s hard cutoff (`opponent_age > reference_age` → bonus fully zeroed) replaced with `_own_age_gate_scale`, a sigmoid centered on `reference_age`, 3-year width. Eliminated the discontinuous jump in a fighter's own score from a marginal (sub-year) change in opponent age.

9. **Bonus Component Columns Persisted.** `title_defense_bonus`, `streak_bonus`, `age_adjustment`, `own_age_adjustment`, `rematch_adjustment` (per `_fighter_1`/`_fighter_2`) now written per-fight — previously computed but discarded. Verified purely additive before the next fix landed: bit-identical `ude_points_post_fight_*` (max abs delta 0.0 across all 8,564 fights).

10. **Rolling-Window/Expanding-Fallback Boundary — measured, not fixed.** At the 2011→2012 transition, the calibration cache switches regimes for the first time (2012 is the first year with ≥1,000 fights in a trailing 5-year window). Measured directly: the 2011→2012 delta in fitted `reference_age`/`own_post_slope`/`opponent_post_slope` is *smaller* than several purely within-regime year-over-year deltas elsewhere (e.g. 2012→2013, 2025→2026) — not a distinguishable artifact. Left as-is.

11. **CRITICAL — Neutral-Calibration NaN Bug in `_age_multiplier`, found and fixed.** Discovered while investigating an unexpected top-20 reshuffle after #7/#8. `_neutral_age_calibration()` (used 1999–2007, insufficient prior history) sets `reference_age = NaN`. The guard `if age <= reference_age: return 1.0` never short-circuits against NaN (all NaN comparisons are False in Python/numpy), so execution fell through into `slope * NaN = NaN` math, and `max(AGE_MIN_MULTIPLIER, min(AGE_MAX_MULTIPLIER, multiplier))` silently resolved that NaN to the concrete 1.5x ceiling instead of a neutral no-op (Python's `min`/`max` keep the first argument compared against NaN). Net effect: every decisive fight scored under neutral age calibration got a flat, unconditional +50% bonus (wins) or 50%-larger penalty (losses) via `age_adjustment` — confirmed on 602/606 fights (99%) across 606 fights (~7% of the dataset) in 1999–2007. `own_age_adjustment` had the same defect independently but was accidentally neutralized as a side effect of #8's explicit `pd.isna(reference_age)` guard — `age_adjustment` alone was still live going into this pass. Fixed by adding the guard directly to `_age_multiplier`.

12. **Two harmless cleanups in `ude_points_algorithm.py`.** `championship_bonus`'s `if result=='W'`/`elif result=='L'` branches did the identical thing (both `points*2.0`) — collapsed to one condition. `dominance_adjustment` accepted a `method_mapped` parameter it never read (the docstring already says "method-neutral") — removed, and its one call site updated. Verified bit-identical output before/after.

13. **Architectural review of `ude_points_feature_engineering_pipeline.py`.** First read-through of this file this session. Findings: a hard threshold cliff in `calculate_phase_magnitude_and_pdi`'s takedown/submission magnitude (fixed, see #15); `map_weight_class`'s substring-based classification was order-dependent and fragile — `"Heavyweight"` is a literal substring of `"Light Heavyweight"`, and correctness relied entirely on dict insertion order (fixed, see #14); `who_won_*`/`dominant_fighter`/`phases_won` and `rematch_column`/`is_rematch` were initially flagged as dead code because `ude_points_algorithm.py` doesn't consume them — **incorrect call, retracted.** These are intentionally retained for narrative/visualization use outside the scoring path (phase-win breakdowns, rematch-depth display); not everything in this pipeline exists to feed UDE scoring.

14. **`map_weight_class` longest-match fix.** Sorted the weight-class dict by name length (descending) before the substring-containment loop, instead of relying on insertion order. Verified against all 100 distinct raw `weight_class` strings in the live dataset: zero output changes — purely defensive, no rescoring needed.

15. **PDI takedown/submission magnitude — smoothed the hard cliff.** `calculate_phase_magnitude_and_pdi`'s `td_mag`/`sub_mag` picked between a "close" formula (capped 0.35) and a "decisive" formula (0.36+) via a hard `count > N and proportion >= P` gate — a real value-gap and a disproportionate jump right at the boundary, on the single most influential input in the whole scoring system (`pdi_margin` drives `dominance_adjustment`, `perf_scale`, and the method residual simultaneously). Replaced with `_dominance_magnitude`: a soft-AND blend (product of two sigmoids, over landed-count and proportion) between the same two curves.
    - First-draft widths (`count_width=1.0`) were checked numerically before shipping and found to reintroduce exactly the problem the original gate existed to prevent: landing 2 of 2 attempted takedowns (a tiny sample) jumped from 0.35 to 0.466 — a 33% inflation for a 2-takedown sample. Root cause: takedown/submission counts are integers, so there's nothing to smooth *between* consecutive counts — a loose width just lets the "decisive" curve bleed into small samples instead of interpolating.
    - Tightened to `count_width=0.10`: 1/1, 2/2, and 3/3 (all landed-vs-opponent's-0) now land within 0.004 of their old capped value — the original small-sample protection is preserved almost exactly. The actual value this fix adds is in the proportion axis (genuinely continuous — no more instant flip at exactly 80%/75%) and in closing the 0.35→0.36 value-gap itself, not in the count axis, which integers make impossible to meaningfully smooth.
    - Recomputed PDI-dependent columns on `v2_6.csv` directly (all raw inputs — strikes, control time, takedowns, submissions, knockdowns — already present; the separately-referenced `all_fights_data_processed_engineered_and_ready_for_ude_points` raw file wasn't needed and isn't present in the project directory). 2,966/8,564 fights (35%) had a `pdi_margin` change, mean magnitude 0.032, max 0.37 — modest, as expected from a fix touching only two of five phase magnitudes. Full UDE re-run: 0 NaN, 0% swing-cap bind, ranking membership and order unchanged (same 20 fighters, same order — values shifted at the 2nd-3rd decimal), stability re-confirmed (18–19/20 overlap across `prior_strength` 5–20).

16. **Second architectural pass on `ude_points_feature_engineering_pipeline.py`, assume-nothing re-derivation.** Re-read the file fresh rather than trusting the first pass's verdict. Two new findings, both verified against real data before acting:
    - **Latent NaN-poisoning risk** in `update_career_means`, `add_dynamic_strike_accuracy`/`_defence`, `add_dynamic_td_accuracy`/`_defence`: each accumulates a per-fighter running total via unchecked `+=`, so one NaN in a raw landed/attempted stat would silently poison that fighter's total — and every derived column built from it — to NaN for the rest of their career. Checked: zero NaN currently present across every column these functions touch, so not live. Fixed anyway with a `fillna(0)` guard at the top of `engineer_all_features`, matching `_to_num`'s existing NaN-as-0 convention elsewhere in the same file — same shape of risk as item #11, deliberately closed before it could ever trigger rather than after.
    - **`standing_sig_strikes_landed_per_min_*` silently never generated.** `add_time_and_per_min_features` (step 9) ran before `add_standing_sig_strikes_columns` (step 10) — the per-minute step scans `df.columns` for every `*_landed`/`*_attempted` column present *at that point*, so the source column for this one variant didn't exist yet when the scan ran. Every other landed-stat got its per-min column; only this one silently didn't. Fixed by swapping the step order (standing-sig-strikes now runs first) — zero dependency conflict either direction.
    - Re-confirmed the PDI-cliff fix, `map_weight_class` fix, and the `who_won_*`/`rematch_column` "not dead code" correction all still hold on fresh reading.

17. **Full clean rebuild, prompted by "make sure old columns aren't sitting beside new ones."** Every fix above through this point had been applied incrementally, patching `v2_6.csv` in place — never a from-scratch rebuild. Attempting one immediately surfaced the exact risk being asked about: `engineer_all_features`'s functions add columns via `pd.concat`, which creates a genuine *duplicate*-named column (not an overwrite) when the input already contains that name — re-running the pipeline against the already-processed file crashed inside `quality_score` with "truth value of a Series is ambiguous," because `is_champion_fighter_1` (and everything else) now existed twice and indexing it returned a Series instead of a scalar.
    - Determined the true raw/derived column split **empirically**, not by manual enumeration (too easy to miss one): ran each pipeline stage in sequence starting from a candidate raw set, checked `df.columns.duplicated()` after every single stage, and fed any collision back into the drop-list for the next attempt. Converged after 19 iterations on a 75-column true-raw base. Manually enumerated the 30 `ude_points_algorithm`-output columns separately (since those are written via safe in-place `.at` assignment, never `pd.concat`, so they don't collide the same way) and verified the guess was exactly complete (0 missing, 0 extra) by diffing before/after `calculate_ude_points_with_ablation`'s own column set.
    - Why the algorithm-output columns needed dropping too, even though `.at` assignment can't duplicate: no-score rows (NC/DQ/Overturned) `continue` before writing most diagnostic columns (`method_pdi_residual`, `title_defense_bonus`, `age_adjustment`, etc.) — so if those columns already held values from a prior run, those specific rows would silently keep stale data forever while every scored row got fresh values. Dropping everything derived first, for every row, was the only way to guarantee no stale leftovers anywhere, not just no duplicate names.
    - Ran the full pipeline (`engineer_all_features` → `calculate_ude_points_with_ablation` → `add_ude_points_difference_columns`) on the clean 75-column base: 8,564 × 256 columns, zero duplicates at every stage. Diffed against the incrementally-patched file: exactly 6 new columns (`standing_sig_strikes_*_per_min_*`, the step-order fix from #16 finally taking effect — the earlier PDI-only patch never touched that part of the pipeline, so it had no way to surface this), everything else within 0.0001 (floating-point noise, not a real difference). Re-verified: 0 NaN, 0% swing-cap bind, ranking identical (same 20 fighters, same order, same values to reported precision), stability reconfirmed (18–19/20 overlap across `prior_strength` 5–20). Promoted as the current `v2_6.csv`.
    - Takeaway for next time: incremental patching is fine for verifying one fix in isolation, but only a full raw-to-final rebuild actually proves the shipped file matches the current code everywhere, not just wherever was last touched.

18. **`dataset_processing_pipeline.py` added to the project; null-event_date rows caught at the source.** User supplied a genuinely raw (pre-feature-engineering) dataset, `fights_up_to_islam_garry_ready_for_features.csv` (8,566 fights, 75 columns), plus the ETL file that produces it. Flagged that 2 of the 8,566 rows had null `event_date` and had been manually dropped before use, and asked where the automated version of that drop should live.
    - `event_date` is created in `run_etl_pipeline` via a left join against `events_df`; a null here means the join found no matching event (here: "Road to UFC 4.5 + 4.6," likely too new for the events source at scrape time). The existing `validate_transformed_data` only tracks an aggregate null *percentage* against a 5% threshold — 2/8,566 (0.02%) would never trip it, so this category of problem was invisible to the file's own validation.
    - Added `drop_rows_with_null_event_date(df)` to `dataset_processing_pipeline.py`, called right after column standardization in `run_etl_pipeline` (the first point `event_date` has its final name) — reports exactly which rows it drops (event name/URL, fight URL, bout, fighter names) rather than discarding silently, since a failed join can also mean the events source itself is missing data worth someone's attention. Also called defensively at the top of `engineer_all_features` (imported from the ETL file), since that function shouldn't have to assume its input necessarily came through the fixed ETL step.
    - Ran the full pipeline (`engineer_all_features` → `calculate_ude_points_with_ablation` → `add_ude_points_difference_columns`) on the raw file: the 2 null rows were caught and reported, 8,564 fights scored, 256 columns, zero duplicates, 0 NaN, 0% swing-cap bind. Compared against the current `v2_6.csv` by `fight_url`: **identical fight set, zero difference in any UDE point across all 8,564 fights.** Strongest validation yet that the pipeline is genuinely reproducible from independent raw data, not merely self-consistent under the reverse-engineered rebuild in #17. `v2_6.csv` didn't need to change.

### Locked GOAT ranking — how the list moved

Three versions were produced same-day as the fixes above landed:
- **v1** (post #1–4, pre #7–11): included Tim Sylvia, Matt Hughes, Chuck Liddell, Randy Couture in the top 20.
- **v2** (post #7–9, pre #11): those four dropped out. At the time this was attributed to the own-age achievement fix not helping loss-heavy careers — **that explanation was incomplete.** The dominant cause was actually #11's bug (still live in v2): all four fighters' early-2000s careers fall inside the 1999–2007 neutral-calibration window and were absorbing the erroneous flat +50%/-50% `age_adjustment` swing on nearly every early fight, inflating v1's numbers for them specifically. v2 accidentally corrected `own_age_adjustment`'s copy of the bug but not `age_adjustment`'s.
- **v3 (final):** both copies of the bug fixed. This is the list `canonical_project_state.md` §2 reflects.

Lesson: a surprising ranking shift is a signal to trace the actual mechanism before explaining it, not to pattern-match to the most recent change.
